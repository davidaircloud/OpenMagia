# Co-op Game Intro

Read `../references/h3-production-contract.md` before authoring.

## Required intake

Collect both player identities, their roles or abilities, reference images, world or menu style, entrance premise, exact title and interface copy, player-side assignment, duration, aspect ratio, tone, and required final menu state. Record whether each reference is a character lock, environment reference, or exact opening frame.

Do not proceed with ambiguous identity ordering or placeholder UI copy. The local refinement model must ask a concise question when either is missing. If the entrance is open-ended, it should offer two or three coordinated concepts—parallel action, rescue-and-return, or competitive convergence, for example—and explain the final menu composition for each.

## Identity and copy locks

For Player 1 and Player 2 independently, lock face or design, silhouette, costume, equipment, palette, scale, signature behavior, and screen side. Also lock world geography, title spelling, button labels, player-card labels, status text, and permitted effects.

Never merge traits, swap sides, duplicate a hero, invent interface copy, or regenerate changing letters throughout the shot. Treat approved words as production assets rather than decorative texture.

## Entrance and convergence plan

Give each hero a complementary entrance that communicates role through action. Establish Player 1, establish Player 2, show a causal interaction or shared objective, converge them into the same composition, then transition to the stable menu. Preserve eyelines, scale, left/right assignment, and world geography throughout.

Every interface activation needs a visible cause and timed response. Avoid unexplained flashes, simultaneous clutter, or UI that obscures faces and equipment.

## H3 scene construction

Write the sequence chronologically with frame or second ranges at 24 fps. Specify camera, entrance action, interaction, effects, UI appearance order, exact on-screen strings, and final hold. Reserve enough time for the final title and buttons to be read.

Use ordered character references and state which reference belongs to which player. Use an approved menu frame only if exact composition is required. If exact typography cannot be guaranteed during generation, plan a clean plate and deterministic OpenMagia text overlay rather than allowing misspelled generated text.

## Local refinement

The local model may enhance action verbs, coordination, effects, camera transitions, audio, and H3-compatible constraint language. It cannot modify either identity, side assignment, exact copy, reference mapping, or approved concept. It must present missing decisions to the user and include the complete installed skill specification when preparing the generation prompt.

## Audio and quality check

Design distinct entrance signatures for each player, a shared convergence hit, restrained game ambience, interface confirmation sounds, and a stable menu bed. Verify both heroes remain recognizable and separate, entrances reveal their roles, UI triggers are motivated, exact copy is readable, and the final screen is held cleanly.

If identities blend, separate entrances and reduce overlap. If copy mutates, render it as an OpenMagia overlay. If the final menu is rushed, simplify the shared action and allocate more frames to the hold.
